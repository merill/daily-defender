Month in brief

Cloud Apps Identity inventory moves to automatic enablement for eligible tenants

The clearest operational change is the scheduled move of the Defender for Cloud Apps Identity inventory integration from opt-in to automatic enablement on October 15, 2026, subject to documented exclusions. Defender for Office 365 is also rolling out promotional-mail tagging and folder handling, while Defender XDR guidance now separates Sentinel-only custom-detection scheduling from Defender XDR lookback behavior. Most remaining updates were maintenance, with the strongest administrator guidance covering Linux golden-image onboarding and Defender for Identity licensing prerequisites.

  • Cloud Apps · Cloud and workloads
    Cloud Apps Identity inventory integration switches from opt-in to automatic

    Starting October 15, 2026, the integration will be enabled automatically for eligible tenants that do not use the listed excluded configurations. Administrators should account for activation without an opt-in step in those tenants.

  • Defender XDR · Email and collaboration
    Defender for Office 365 rollout tags promotional mail and learns from moves

    Promotional emails will be tagged as “promotions” and can be moved automatically to a Promotions folder, with the system learning from user actions. Public preview starts in mid-April 2026 and general rollout is scheduled to complete by late 2026; administrators control the settings and users can customize handling by moving messages.

  • Defender XDR · Hunting and detection
    Custom detection scheduling now distinguishes Sentinel and Defender XDR data

    Custom frequency from 5 minutes to 14 days is limited to rules based exclusively on Microsoft Sentinel data. Rules using Defender XDR data use fixed lookback periods tied to run frequency, ranging from 4 hours to 30 days, so authors should verify the data source and expected coverage.

  • Endpoint · Endpoint protection
    Linux golden-image onboarding adds hostname-safe startup sequencing

    The deployment procedure says to embed the tenant-specific onboarding file in the image, keep `mdatp` stopped during image creation, and start Defender on clones only after each final hostname is set. It also adds onboarding and health checks and calls for protecting tenant-specific onboarding files to prevent copied device identity state or incorrect hostnames.

  • Identity · Identity protection
    Identity sensor activation guidance adds an active-license prerequisite

    The activation guidance now states that automatic sensor activation and automatic Windows auditing require an active license that includes Microsoft Defender for Identity. The domain-controller onboarding heading also no longer labels the process as preview.

For Defender administrators

Cloud Apps administrators should review the documented exclusion conditions and account for automatic activation in eligible tenants from October 15. Detection authors should verify the data source and lookback coverage; Linux image owners should sequence Defender startup after final hostname assignment and protect tenant-specific onboarding files; Identity administrators must verify an active Defender for Identity license before relying on automatic sensor activation or Windows auditing.
