Month in brief

Defender RBAC auto-enablement and Office 365 permission changes begin in December

November’s consequential changes center on access control and email response. Defender RBAC will auto-enable beginning in December 2026, the Entra Security Operator mapping will lose default access to Defender for Office 365 email threat policies and the Tenant Allow/Block List, and Plan 2 is gaining a Move to Quarantine remediation action in late November. The strongest documentation work adds operational boundaries for local AI-agent discovery and Arc-proxied Defender for SQL; other updates are primarily release, troubleshooting, or wording maintenance.

  • Defender XDR · Identity protection
    Defender RBAC will auto-enable from December 2026

    The unified Defender RBAC model will be enabled in the tenant starting in December and will unify access management for Defender and Sentinel. Existing roles will be imported for review, with activation occurring about 30 days after notification; other Microsoft service permissions remain unchanged.

  • Defender XDR · Email and collaboration
    Security Operator mapping loses default email-policy access

    Microsoft is removing default access to Defender for Office 365 email threat policies and the Tenant Allow/Block List from the Microsoft Entra Security Operator mapping. The change begins rolling out in December 2026, so continued access requires manually assigned permissions.

  • Defender XDR · Email and collaboration
    Plan 2 adds Move to Quarantine for suspicious email

    Defender for Office 365 Plan 2 is introducing a remediation action that moves suspicious messages from user mailboxes into Defender quarantine for investigation and management. Rollout begins in late November 2026; Microsoft recommends reviewing relevant policies and roles.

  • Endpoint · Endpoint protection
    Local AI-agent discovery guidance defines inventory and access boundaries

    The updated guidance says observing an agent process can create an inventory entry without a prompt or service permission, but discovery does not prove active use or successful access. It also documents minimum Defender versions and the Unified RBAC permissions needed to view inventory and the attack surface graph.

  • Defender for Cloud · Cloud and workloads
    Defender for SQL guidance documents Arc-proxy support at version 2.0.3585.403

    The release notes now document support for Azure Arc SQL Server instances with Arc proxy enabled when the Defender for SQL extension is version 2.0.3585.403. The version is available for manual update, while automatic rollout has not started; environments without direct internet access can use the Arc proxy for outbound communication.

For Defender administrators

Review the Defender and Sentinel roles that will be imported before Defender RBAC activation and adjust them as needed; Microsoft says opt-out is available after activation. Explicitly assign Defender for Office 365 permissions to Security Operator users who still need email-policy or Tenant Allow/Block List access. Before the Move to Quarantine rollout, review relevant policies and roles. For local AI-agent inventory, verify the documented minimum Defender versions and Security for AI and Exposure Management permissions. For Arc-proxied SQL Server coverage, verify the Defender for SQL extension version and outbound connectivity requirements; version 2.0.3585.403 is available for manual update and automatic rollout has not started.
