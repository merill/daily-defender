Day in brief

Defender for Endpoint and Servers guidance details unified inventory, hunting, and RBAC

This documentation-heavy period’s most consequential updates describe a combined Defender for Endpoint and Defender for Servers experience in the Microsoft Defender portal, clarify when disabling Defender for Servers automatically offboards eligible servers, and replace manual support-log analyzer steps with self-contained Live Response workflows. Sentinel normalization guidance also adds a unified process-event parser pattern, while most remaining edits are narrower reference, navigation, or release-entry maintenance.

  • Endpoint · Endpoint protection
    Unified server experience guidance consolidates endpoint and server workflows

    The Endpoint page now describes bringing Defender for Endpoint and Defender for Servers together in the Microsoft Defender portal for Azure and on-premises servers, covering server asset views, investigations, hunting, RBAC, and device groups. It states that existing Defender for Endpoint servers require no onboarding, reinstallation, or migration; administrators should still review capability requirements before changing configuration.

  • Defender for Cloud · Architecture and deployment
    Offboarding guidance distinguishes disabling Defender for Servers from a Plan 2-to-Plan 1 switch

    The Defender for Cloud tutorial states that disabling Defender for Servers for Azure subscriptions in public preview automatically offboards eligible servers, while switching from Plan 2 to Plan 1 does not trigger automatic offboarding. Administrators should account for that distinction when changing coverage.

  • Endpoint · Troubleshooting
    Collect Support Log guidance moves to self-contained binary and Python actions

    The updated Endpoint procedure replaces manual analyzer-download steps with self-contained binary or Python Live Response action pairs, adds package validation and workspace-ID handoff, and specifies prerequisites and HTTPS requirements. It also documents a local workflow for devices without Microsoft endpoint access; binary actions do not require Python, while Python actions do.

  • Sentinel · Developer and API
    Sentinel normalization guidance adds the unified imProcessEvent parser

    The normalization schema page now documents imProcessEvent for querying all process event types while retaining specialized parsers. It also revises custom-parser naming guidance and the filtering example, giving parser owners updated names and query patterns to apply.

  • Exposure Management · Developer and API
    Azure DevOps connector setup now starts in Agentic code scanning management

    The Exposure Management guide directs administrators to Agentic code scanning management, select Add another beside Source code environment, and choose Azure DevOps to open the connector flow. Connector configuration should follow that updated navigation.
