Day in brief

AI agent support matrix clarifies Defender for Endpoint’s activity-based discovery

The period’s most consequential administrator guidance concerns local AI agents in Microsoft Defender for Endpoint. A new support matrix covers supported agents, MCP server discovery, and runtime protection by operating system and configuration, while related pages clarify that discovery depends on observed activity. Sentinel also added specific custom-parser guidance. Most remaining updates—32 in Microsoft Security Exposure Management—were page-attribution maintenance.

  • Endpoint · Endpoint protection
    New matrix separates AI agent support by operating system and configuration

    A new Microsoft Defender for Endpoint article documents supported local AI agents, MCP server discovery, and runtime protection scenarios, with support listed separately by operating system and configuration. It also explains that discovery depends on observed agent activity.

  • Endpoint · Endpoint protection
    Installed agents may remain absent until Defender observes activity

    The local-agent guidance states that Defender lists an agent after observing activity on an onboarded device; installation alone does not guarantee discovery. It also says the inventory is not a complete software inventory, directing administrators to Software inventory for installed-software details and the support matrix for coverage.

  • Endpoint · Endpoint protection
    Runtime protection guidance broadens inspection-point terminology

    The AI Agent Runtime Protection overview now uses broader descriptions of inspection points, streamlines its explanations of agent-native and network inspection, updates discovery terminology, and removes the explicit event-point list and vendor links.

  • Sentinel · Cloud and workloads
    Sentinel parser guidance sets disabled=false and conditions pack forwarding

    Normalization guidance now explains that the generated table sets `disabled=false` to enable custom parsers and advises forwarding `pack` only when the source-specific parser supports it. Review custom unifying parser functions for these parameter expectations.

  • Exposure Management · Developer and API
    Exposure Management updates largely change page attribution

    A broad Microsoft Security Exposure Management sweep changed author metadata across connector, attack-surface, and vulnerability/exposure pages. For example, the OT data connectors page now credits DebLanger instead of limwainstein/lwainstein. These edits indicate no administrator action.
