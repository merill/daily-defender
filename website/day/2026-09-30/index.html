Day in brief

Foundational CSPM will default off for new Azure subscriptions October 27

The main operational change is a Defender for Cloud default-setting shift: Foundational CSPM will remain free but will no longer be enabled automatically for new Azure subscriptions from October 27, 2026. Related updates clarify Defender for Servers billing treatment, while Defender for Office 365 is adding email-submission data to Advanced Hunting. Office 365 guidance also tightens the documented format for Punycode URLs.

  • Defender for Cloud · Cloud and workloads
    Foundational CSPM default changes for new Azure subscriptions

    Starting October 27, 2026, Foundational CSPM will no longer be enabled by default for new Azure subscriptions. The plan remains free and can be enabled at any time; existing subscriptions and AWS or GCP environments are unaffected.

  • Defender for Cloud · Cloud and workloads
    Defender for Servers revises device classification and server counting

    Plan 1 will no longer bill desktop, workstation, and mobile devices as servers. For Plans 1 and 2, server identification will run more frequently and count deployed machines individually, which may change billed server totals.

  • Defender for Cloud · Cloud and workloads
    Starting-state VMs are included in Defender for Servers billing guidance

    The Defender for Servers FAQ now states that virtual machines in the Starting power state are billed and links to upcoming billing updates. Administrators should include these VMs when estimating costs.

  • Defender XDR · Hunting and detection
    Advanced Hunting adds email submission telemetry tables

    Microsoft Defender for Office 365 will add the SubmissionEvents and SubmissionResults Advanced Hunting tables, rolling out worldwide in early October 2026. They provide enhanced visibility into email submissions and support tailored detection workflows; no immediate action or compliance change is required.

  • Office 365 · Email and collaboration
    Tenant Allow/Block List guidance limits Unicode and Punycode URL formats

    The documentation now states that Unicode is unsupported and that Punycode is allowed only in hostname labels before a normal ASCII top-level domain. Configured Punycode URLs should follow that format.
