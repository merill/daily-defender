Tuesday, 20 October 2026

Day in brief

Defender for Cloud portal preview adds Azure plan management and DWU cost guidance

The substantive changes on 20 October center on the Defender for Cloud portal preview: new guidance covers connecting Azure commercial environments, configuring plans globally or by scope, migration effects, and Defender Workload Unit (DWU) cost estimation and reporting. Separate Defender for Identity updates expand documented sensor v3.x onboarding without Defender for Endpoint to eligible Windows Server 2019 or later AD FS, AD CS, and Microsoft Entra Connect servers, while clarifying safe offboarding. Direct onboarding guidance also makes its tenant-wide scope explicit. Supporting edits mainly refine server procedures, portal boundaries, sensor coverage, and threat-intelligence references, with some routine metadata changes.

  • Defender for Cloud · Cloud and workloads
    Defender for Cloud portal plan management is documented as a preview

    New guidance covers global or scoped plan configuration for connected Azure commercial environments and the required permissions. Global enablement migrates current environments and applies to future ones; after migration, Azure portal plan settings are view-only and resource-level configurations are not preserved.

  • Defender for Cloud · Cloud and workloads
    DWU guidance adds cost estimation and reporting

    New billing guidance introduces Defender Workload Units, a Cloud Security Cost Estimator, and a cloud security cost report. It also describes revised workload measurements, plan consolidations, and DNS billing treatment, helping administrators map existing coverage to DWUs.

  • Defender for Cloud · Cloud and workloads
    Direct onboarding guidance makes tenant-wide scope explicit

    The procedure states that Direct onboarding affects all eligible existing and future non-Azure servers in the same Microsoft Entra tenant; individual-server or pilot-group selection is not supported. Prerequisites include healthy Defender for Endpoint telemetry, a matching tenant, and specified roles.

  • Identity · Identity protection
    Defender for Identity lists sensor v3.x onboarding for more server roles

    Updated guidance lists sensor v3.x activation without Defender for Endpoint for eligible AD FS, AD CS, and Microsoft Entra Connect servers running Windows Server 2019 or later, in addition to eligible domain controllers.

  • Identity · Identity protection
    Sensor v3.x offboarding must precede portal deletion

    For v3.x sensors deployed without Defender for Endpoint, the updated procedure says to run the offboarding package on the server before deleting its portal entry. Deleting the entry alone may leave the sensor active, sending data, and able to reactivate.
