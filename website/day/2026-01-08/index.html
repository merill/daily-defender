Day in brief

Defender endpoint API guidance standardizes on `api.security.microsoft.com` across integration examples

The period’s most consequential update is a broad Endpoint API reference pass: documented request URLs, OData context and response links, and sample integrations replace `api.securitycenter.microsoft.com` with `api.security.microsoft.com`; one app-partner example also updates its resource URI and OAuth scope. Separately, Microsoft added Teams blocking guidance and made Unified SecOps onboarding prerequisites and guest limitations explicit. Most other supplied edits are formatting, navigation, terminology, or API-table cleanup.

  • Endpoint · Vulnerabilities and exposure
    Endpoint API references adopt the `api.security.microsoft.com` hostname

    Many Endpoint API reference pages now replace `api.securitycenter.microsoft.com` with `api.security.microsoft.com` in requests and OData examples. On the Get Machine Group Exposure Score page, both the GET endpoint and sample `@odata.context` URL changed; administrators maintaining scripts should update copied references.

  • Office 365 · Email and collaboration
    Tenant Allow/Block List guidance now covers Teams domain blocking

    New guidance explains how to use the Tenant Allow/Block List to block domains and email addresses in Microsoft Teams. It documents prerequisites, roles, limits, expected timing, and the resulting impact: existing communications can be removed and new meetings, chats, channels, and calls blocked.

  • Unified SecOps · Vulnerabilities and exposure
    Unified SecOps onboarding adds Plan 2 and Azure B2B constraints

    The revised playbook combines environment preparation and customer onboarding, renumbers the sequence into three steps, and revises delegated-access guidance. It explicitly documents Defender for Office 365 Plan 2 as a prerequisite for Unified RBAC and records limitations for Azure B2B guests.

  • Endpoint · Endpoint protection
    Security-baseline API documentation no longer lists id and CCE filters

    Get Security Baselines Assessment Configurations now links to OData guidance and examples and lists filtering on category and name; the previously displayed `id` and `CCE` filter properties are no longer shown. Review integrations that rely on those fields.

  • Defender XDR · General
    Security Copilot pages add dedicated Threat Hunting and Dynamic Detection guidance

    The Security Copilot Agents Defender page now includes sections for the Threat Hunting Agent and Dynamic Threat Detection Agent, with a link and screenshot for threat-hunting workflows. The additions make natural-language investigations and adaptive detection guidance easier to locate across Defender and Microsoft Sentinel.
