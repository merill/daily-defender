Transition Custom Detections Automatic

22 November 2026Doc update+19 / −21 lines

In brief

The page now states that migrated rules automatically convert affected JSON columns when they run. Queries copied into advanced hunting still require `todynamic()` before accessing nested JSON values. Documentation for two unavailable `ExtendedProperties` fields was also removed.

What Defender admins need to know

No action is required. Administrators copying migrated-rule queries into advanced hunting should add the documented JSON parsing step.

Note

Migrated rules handle JSON-column conversions automatically when they run. If you copy a rule's query into advanced hunting, parse JSON-string columns such as DeviceEvents.AdditionalFields and DeviceNetworkInfo.ConnectedNetworks, are dynamic in Log Analytics but JSON-formatted strings in advanced hunting. Parse the column with todynamic() before accessing a property or array element,nested values, for example, todynamic(AdditionalFields).Property or todynamic(ConnectedNetworks)[0]. Use tostring() when comparing extracted values with text. Migration applies this conversion automatically for scheduled analytics rules. For streaming (NRT) rules, direct nested access to affected columns is an eligibility blocker: update the source analytics-rule query, then reassess eligibility. Apply the same parsing when manually running the original query in advanced hunting. Validate changes against representative data in both environments; other schema differences and migration blockers can still require changes.
