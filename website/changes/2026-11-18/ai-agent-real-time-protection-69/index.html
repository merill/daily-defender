Ai Agent Real Time Protection

18 November 2026Generally available+11 / −7 lines

In brief

The documentation now lists Microsoft Foundry agents, Copilot Studio agents, and Agent 365 Tooling Servers (WorkIQ and custom MCP) as supported types. Tooling Servers cover tool invocations and responses; Foundry covers requests, responses, and tool activity, while Copilot Studio currently covers tool invocations only.

What Defender admins need to know

No administrator action is stated. Use these coverage limits when planning AI-agent protection and monitoring.

To detect, investigate, and hunt for AI agent threats after they occur, see Detect and investigate threats to AI agents using Microsoft Defender.

Note

Real-time protection policies currently support Microsoft Foundry agents, Microsoft Copilot Studio agents, and Agent 365 Tooling Servers (WorkIQ and Custom MCP) only. Support for additional agent types is not yet available.

Prerequisites

  • Enable security for AI agents, including the Microsoft 365 app connector. See Enable security for AI agents using Microsoft Defender.
  • To protect Copilot Studio agents in real time, make sure Copilot Studio is connected. See Enable security for AI agents using Microsoft Defender.
  • Local agents are onboarded separately from cloud agents. To protect local AI agents that run on endpoints, set up AI agent runtime protection in Microsoft Defender for Endpoint. Microsoft Defender for Endpoint must run in active mode.

For cloud agents, thereThere are two types of real-time protection rules:

  • Default rule: Audits all agents, recording matching activity as a behavior without stopping the action. This gives you visibility before you enforce blocking.
  • Custom rules: Block matching actions before they execute and record the behavior. Create custom rules for high-confidence threats and scope them to specific agents.

When Microsoft Defender audits or blocks an action, it records the event as a behavior in the BehaviorInfo table, including what happened, why the action was considered risky, and which agent, user, and tool were involved. Security teams can query these behaviors to build custom detections, hunting queries, and downstream automation. Near-real-time detections continue to surface as alerts only in audit mode. When a blocking rule covers an agent, near-real-time alerts aren't generated for that agent.
