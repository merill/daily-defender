14 October 2026Doc update+20 / −3 lines

In brief

The instructions now use Create > Logic App playbook and distinguish Consumption triggers—including alert, case, and legacy options—from Standard playbooks, which start with Blank playbook. The page also explains case-versus-incident terminology and adds supporting links.

What Defender admins need to know

Administrators creating playbooks should follow the revised menu path and select the option matching the playbook type and trigger.

  1. From the top menu, select Create > Logic App playbook, and then select one of the following options:

    • If you're creating a Consumption playbook, select one of the following options, depending on the trigger you want to use, and then follow the steps to prepare a Consumption logic app playbook:

      • Playbook with alert trigger: Create a playbook that runs in response to an alert.
      • Playbook with case trigger: Create a playbook that runs in response to a case in Microsoft Defender.
      • Playbook with incident trigger (Legacy): Create a playbook that uses the legacy incident trigger.
      • Playbook with alert trigger (Legacy): Create a playbook that uses the legacy alert trigger.
      • Playbook with entity trigger (Legacy): Create a playbook that uses the legacy entity trigger.

      In this example, select Playbook with entity trigger (Legacy).

    • If you're creating a Standard playbook, select Blank playbook and then prepare a Standard logic app playbook.

    Note

    Microsoft Defender uses the term case, while Azure Logic Apps uses incident terminology for the corresponding Microsoft Sentinel connector triggers and actions. When you create a playbook with a case trigger in Microsoft Defender, the corresponding trigger in Azure Logic Apps is called Microsoft Sentinel incident.

    For more information, see Supported logic app types and Supported triggers and actions in Microsoft Sentinel playbooks.
