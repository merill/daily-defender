Migrate To Sensor V3

14 October 2026Feature updateAction required+7 / −5 lines

In brief

The prerequisite changed from the July 2026 to the September 2026 or later Windows Server cumulative update. Post-migration guidance now covers manually removing workspace DSA or gMSA configuration and retiring unused gMSA accounts after verifying they have no other users.

What Defender admins need to know

Update eligible servers to the September 2026 or later cumulative update. After all v2.x sensors migrate, remove obsolete workspace configuration and retire only gMSA accounts confirmed to be unused.

Clean up the v2.x sensor

The migration disables the v2.x sensor service, but the v2.x sensor software remains installed on the server. Complete the following cleanup steps to fully clean your server from the v2.x sensor files:after migration:

  • Uninstall the v2.x sensor: Remove the v2.x sensor software from the server. This step might require a server restart. For instructions, see Delete and uninstall a sensor v2.x from a domain controller. \ No newline at end of file
  • Remove Npcap: Npcap was used by the v2.x sensor but isn't required by the v3.x sensor. If Npcap isn't used by other applications on the server, remove it. Leaving Npcap installed doesn't affect the v3.x sensor. \ No newline at end of file
  • Remove workspace DSA or gMSA configuration: Wait until all sensors are migrated to v3.x and no remaining v2.x sensors require the account. Then manually remove the workspace-level DSA or gMSA configuration. Migration doesn't remove this configuration automatically.
  • Retire unused gMSA accounts: Removing the workspace configuration doesn't delete the gMSA account in Active Directory. Before retiring the account, verify that no other services use it. For guidance, see Deprovision service accounts. \ No newline at end of file
