Deploy Sensor V3

14 October 2026Feature updateAction required+15 / −7 lines

In brief

The prerequisite changed from the July 2026 to the September 2026 Windows Server cumulative update for sensor version 3.0.10 or later. The guidance also clarifies v2 migration account settings and that migration does not automatically remove workspace DSA or gMSA configuration.

What Defender admins need to know

Install the September 2026 cumulative update before installing or upgrading the sensor, and select the local system account option before migrating from sensor v2.x.

Supported server types

The v3.x sensor uses the local system identity of the server for both purposes. It doesn't use Directory Service Accounts (DSA) or group Managed Service Accounts (gMSA). LocalSystem is the only supported identity for v3.x.

If you'reBefore migrating from sensor v2.x and previously had a gMSA configured for action accounts,x, select Automatically use the sensor's local system account in the Microsoft Defender portal (Settings > Identities > Microsoft Defender for Identity > Manage action accounts). Migration doesn't change this action account setting automatically. The v3.x sensors don't use gMSA accounts configured for v2.x sensors.

Important

If your workspace still has a Directory Service Account (DSA) or group Managed Service Account (gMSA) configured because v2.x sensors on AD FS, AD CS, or Entra Connect servers still require it, DSA and gMSA credentials continue to be validated on all sensors in the workspace, including v3.x sensors. If DSA or gMSA credential validation fails, the Directory services user credentials are incorrect health alert appears. Workspace-level validation of DSA and gMSA credentials on all sensors is by design. Defender for Identity validates DSA and gMSA credentials at the workspace level for all sensors as long as those accounts exist, regardless of whether individual sensors use them for auditing or response actions.

Defender for Identity v3.x sensors ignore the DSA and gMSA for auditing and response actions, but they're still included in workspace-level credential validation. Migration doesn't remove the workspace-level DSA or gMSA configuration automatically. To stop receiving this health alert on v3.x sensors, manually remove the workspace-level DSA or gMSAconfiguration after all sensors are fully migrated to v3.x and no v2.x sensors require it. Removing the workspace configuration doesn't delete the gMSA account in Active Directory.

Configure RPC auditing

Install the JulySeptember 2026 or later Windows Server cumulative update before you install or upgrade to Defender for Identity sensor version 3.0.810 or later. Starting with sensor version 3.0.8, RPC auditing is enabled automatically on domain controllers, so you no longer need to apply an RPC configuration tag. The related health alert clears shortly after the upgrade.
