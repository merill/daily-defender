Geographical Availability Data Residency

24 November 2026Doc update+33 / −24 lines

In brief

The region table now separates data lake support for separate onboarding from workspace built-in lake tier onboarding, with guidance based on onboarding date and experience. It also documents differing supported regions and notes that built-in onboarding does not require separate data lake onboarding or billing setup.

What Defender admins need to know

When checking data residency or planning deployments, use the column matching the onboarding experience and date. No administrator action is stated.

Summaries are generated from the documentation change itself.

Documentation change

View full page diffView on Microsoft Learn

The comparison below shows only the changed extract. Use the full-page view for complete context.

The following table shows the supported regions for Microsoft Sentinel SIEM and data lake.

Choose the data lake column that matches when and how you onboarded:

  • Separate data lake onboarding, September 2025 to September 2026: If you onboarded to Microsoft Sentinel data lake through the separate data lake setup, use this column. The data lake onboarding guidance continues to apply to this experience.
  • Workspace built-in lake tier onboarding, on or after September 2026: If you onboarded to the Sentinel workspace built-in lake tier, use this column. This experience doesn't require separate data lake onboarding or billing setup. Complete Microsoft Sentinel onboarding, connect your workspace to the Defender portal, and enable the lake tier through Table management. For more information, see Integrated Microsoft Sentinel SIEM and data lake onboarding.

For September 2026 onboarding, use the column that matches the onboarding experience you used.
