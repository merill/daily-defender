In brief

The documentation states that Defender surfaces supported AI agents and MCP servers after observing activity on onboarded devices. An installed agent may not appear until it becomes active; the guidance also adds comparing query results with the discovery support matrix.

What Defender admins need to know

Administrators should account for this delay when reviewing AI agent inventory and advanced hunting results.

Discover local AI agents with Microsoft Defender for Endpoint - Microsoft Defender for Endpoint | Microsoft Learn

Microsoft Defender automatically discovers supported local AI agents and their MCP servers configuredafter it observes agent activity on onboarded devices and surfaces them in the AI agent inventory and advanced hunting. An installed agent might not appear until Defender observes agent activity. To learn more about local AI agent discovery, see Local AI agent discovery with Microsoft Defender for Endpoint. For coverage by agent, operating system, and MCP server configuration, see Microsoft Defender for Endpoint AI agent support matrix.

In this article, you learn how to view discovered agents in the inventory, review their configuration and risk, explore their relationships with devices and identities, and investigate agent presence using advanced hunting.

Table What it contains Use it to answer
AgentsInfo A profile record for every AI agent that Microsoft Defender discovers, acrossdiscovers on all agent platforms. For local AI agents, the record includes the publisher, version, host process, trust and auto-approve settings, configured MCP servers, and the device and account where the agent was seen. What is this agent, and how is it configured?

Each AgentId represents one agent profile, which is a single agent on a single device for a single account. Installations counts those profiles, so an agent that two people use on the same device counts twice, while DeviceCount counts the device once.
