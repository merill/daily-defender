Move To Defender

1 November 2026Doc update+18 / −4 lines

In brief

The page now explains that Azure Monitor Private Link Scope supports Sentinel data ingestion into Log Analytics, but not querying through Defender portal experiences or Defender APIs when query access is restricted to private endpoints. Disabling public Log Analytics query access makes the data unavailable to experiences such as Advanced Hunting.

What Defender admins need to know

Administrators using AMPLS should account for this query limitation when restricting Log Analytics access to private endpoints.

Private Link support

Azure Monitor Private Link Scope (AMPLS) provides private connectivity to Azure Monitor resources, including Log Analytics workspaces. For more information about configuring and using Private Link with Azure Monitor, see Use Azure Private Link to connect networks to Azure Monitor

For Microsoft Sentinel in the Defender portal, AMPLS supports private data ingestion, but it doesn't support querying Sentinel data through Defender portal experiences or Microsoft Defender APIs when Log Analytics query access is restricted to private endpoints.

Specifically:

  • Supported: Microsoft Sentinel data ingestion into the Log Analytics workspace through AMPLS.
  • Not supported: Querying that Sentinel data through Microsoft Defender portal experiences, such as Advanced Hunting, when Log Analytics query access is restricted to AMPLS/private endpoints.
  • Customer impact: If public Log Analytics query access is disabled, Sentinel data in the Log Analytics workspace won't be available to Defender portal experiences that query Sentinel workspace data, including Advanced Hunting.

Configure multi-workspace and multitenant management

Defender supports one or more workspaces across multiple tenants through the Microsoft Defender multitenant portal, which serves as a central place to manage incidents and alerts, hunt for threats across tenants, and lets Managed Security Service Partners (MSSPs) see across customers.
