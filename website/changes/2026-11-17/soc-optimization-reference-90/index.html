Soc Optimization Reference

17 November 2026New feature+25 / −4 lines

In brief

The documentation now describes recommendations for Microsoft Defender XDR tables ingested into Sentinel when the same data is available in Defender for 90 days. Recommendations identify dependent analytics rules, workbooks, and playbooks, and explain the effects of stopping ingestion.

What Defender admins need to know

Review dependent content before using Configure workspace. It stops supported table ingestion together, with exceptions for tables retained 180 days or more; cost savings occur only after ingestion stops.

- **AI MITRE ATT&CK tagging recommendations (Preview)**: Uses artificial intelligence to suggest tagging security detections with MITRE ATT&CK tactics and techniques.
- **Risk-based recommendations (Preview)**: Recommends implementing controls to address coverage gaps linked to use cases that may result in business risks or financial losses, including operational, financial, reputational, compliance, and legal risks.
  • Similar organizations recommendations suggest ingesting data from the types of sources used by organizations which have similar ingestion trends and industry profiles to yours.
  • Lower Defender data costs recommendations find Microsoft Defender XDR tables that you ingest into a Microsoft Sentinel workspace when the same data is already available in Microsoft Defender.

This article provides a detailed reference of the types of SOC optimization recommendations available.

Considerations

  • A workspace only receives similar organization recommendations if the machine learning model identifies significant similarities with other organizations and discovers tables that they have but you don't. SOCs in their early or onboarding stages are more likely to receive these recommendations than SOCs with a higher level of maturity. Not all workspaces get similar organizations recommendations. \ No newline at end of file
  • The machine learning models never access or analyze the content of customer logs or ingest them at any point. No customer data, content, or personal data (EUII) is exposed to the analysis. Recommendations are based on machine learning models that rely solely on Organizational Identifiable Information (OII)organization-level metadata and system metadata.

Lower Defender data costs recommendations

SOC optimization shows a Lower Defender data costs recommendation when a Microsoft Defender XDR table is ingested into a Microsoft Sentinel workspace, and the same data is available in Microsoft Defender for 90 days as part of ISOC. SIEM features can query this data in Microsoft Defender. For more information, see Data ingestion, retention, and billing for ISOC.

Each recommendation covers one table in one workspace. The recommendation shows the analytics rules, workbooks, and playbooks that use the table.

Completing a recommendation doesn't lower costs by itself. Costs go down only after you stop ingestion for the supported Defender XDR tables with Configure workspace.

Important

You can't stop ingestion for a single table. Configure workspace stops ingesting data into Log Analytics for the supported Defender XDR tables in the workspace at the same time, except tables with analytics retention set to 180 days or more, which stay ingested. Before you select it, make sure no analytics rules, workbooks, playbooks, or other content still use these tables in Log Analytics, and that you don't need to keep any of them in Log Analytics for compliance or other reasons.
