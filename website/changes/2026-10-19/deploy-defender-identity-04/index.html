Architecture and deployment

Deploy Defender Identity

19 October 2026Feature update+3 / −3 lines

In brief

The deployment guidance now links to v2.x server requirements and migration prerequisites. It specifies that in-place migration from sensor v2.x to v3.x is currently available only for eligible domain controllers, not other servers.

What Defender admins need to know

Check server roles and prerequisites before planning sensor deployment or migration; non-domain-controller servers require a different migration approach.

Select your deployment method

The sensor version you deploy depends on the server role and operating system. Use the following table to select the appropriate deployment for each server in your environment.recommended deployment. For supported v2.x platforms, see v2.x server requirements. Review the migration prerequisites separately before upgrading an existing v2.x sensor.

For eligible domain controllers running Windows Server 2019 or later, sensor v3.x supports onboarding with or without Microsoft Defender for Endpoint deployment. Other eligible identity-role servers require Defender for Endpoint onboarding.

  • If the server is onboarded to Microsoft Defender for Endpoint, activate sensor v3.x from the Sensor management tab.
  • If an eligible domain controller isn't onboarded to Defender for Endpoint, download and run the sensor v3.x onboarding package.
  • If the serveran eligible domain controller already runs sensor v2.x, migrate the sensor to v3.x. In-place migration isn't yet available for servers that aren't domain controllers.
  • If the server supports sensor v2.x only, install sensor v2.x.
