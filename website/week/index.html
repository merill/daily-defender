Week in brief

Defender brings server operations together as Teams QR-code protection rolls out

The substantive changes this week center on a combined Defender server experience, post-delivery protection for malicious URLs embedded in Teams QR codes, and a private preview expanding Vulnerability Management to selected developer packages. Defender for Cloud also documents plan-driven server offboarding behavior, while Defender for Identity adds a constrained sensor v3.x activation path for eligible domain controllers. Most remaining updates were schema, procedure, navigation, or wording maintenance.

  • Endpoint · Endpoint protection
    Defender for Endpoint and Defender for Servers share a server experience

    The updated guidance describes combined server asset views, investigations, hunting, RBAC, and device groups in the Defender portal for Azure and on-premises servers. Existing Defender for Endpoint servers require no onboarding, reinstallation, or migration.

  • Defender XDR · General
    Teams QR codes gain post-delivery malicious-URL protection

    Microsoft Defender for Office 365 is extending Teams URL protection to detect malicious URLs encoded in QR codes after delivery, warn users, and support investigation through Advanced Hunting. Worldwide rollout is planned for October through November 2026.

  • Defender XDR · Vulnerabilities and exposure
    Vulnerability Management previews coverage for developer packages

    The private preview covers selected Node.js, Python, and Java package vulnerabilities on Windows devices and feeds existing workflows, APIs, and exports. The planned September-to-December 2026 rollout may increase data volume, so integrations should be validated before enablement.

  • Defender for Cloud · Architecture and deployment
    Defender for Cloud clarifies plan-driven server offboarding

    For Azure subscriptions in public preview, disabling Defender for Servers automatically offboards eligible servers. Switching from Plan 2 to Plan 1 does not trigger automatic offboarding.

  • Identity · Identity protection
    Defender for Identity documents sensor v3.x activation without Defender for Endpoint

    The method applies to new sensor v3.x deployments on eligible Windows Server 2019 or later domain controllers. Automatic sensor activation and automatic Windows auditing require an active license that includes Microsoft Defender for Identity.

For Defender administrators

Existing Defender for Endpoint servers require no onboarding, reinstallation, or migration for the combined server experience, but administrators should review capability requirements. No user action is required for the Teams QR-code rollout; review related protection settings and investigation processes. For the Vulnerability Management preview, prepare for increased data volume and validate API and export integrations before enabling. Verify licensing and eligibility before using the Defender for Identity activation path, and treat disabling Defender for Servers as an offboarding operation; changing from Plan 2 to Plan 1 does not automatically offboard servers.
