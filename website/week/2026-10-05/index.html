Week in brief

Teams QR protection and new Defender hunting tables headline the week

The period was documentation-heavy, with many Exposure Management entries changing only author metadata. The substantive administrator-facing changes were post-delivery Teams QR-code protection, new Defender for Office 365 hunting tables, unified server-management guidance, a Kubernetes recommendation-scope change, and a Sentinel connector for SAP BTP vulnerability findings.

  • Defender XDR · General
    Teams QR-code protection moves into post-delivery detection

    Microsoft Defender for Office 365 is extending Teams URL protection to detect malicious URLs in QR codes after delivery, warn users, and expose the activity for Advanced Hunting. Worldwide rollout is scheduled for October through November 2026, with no user action required.

  • Defender XDR · Hunting and detection
    SubmissionEvents and SubmissionResults expand Defender hunting data

    Two new Advanced Hunting tables will provide Microsoft Defender for Office 365 email-submission visibility. Public Preview starts in early October 2026 and General Availability begins in late October 2026; the announcement states that no immediate action or compliance change is required.

  • Defender for Cloud · Cloud and workloads
    Server guidance documents unified Endpoint and Defender for Servers workflows

    Updated Defender for Cloud release notes describe combined Defender for Endpoint and Defender for Servers data for unified inventory, cross-service investigations, Go hunt, and access through RBAC, device groups, and cloud scopes. They also document offboarding eligible servers by disabling Defender for Servers for a subscription.

  • Defender for Cloud · Cloud and workloads
    KSPM recommendations now target Kubernetes workload controllers

    Starting October 5, 2026, Defender for Cloud KSPM misconfiguration recommendations align with Kubernetes workload controllers rather than individual running container instances. Teams should adjust how they locate and triage these findings.

  • Sentinel · Cloud and workloads
    Sentinel reference adds SAP BTP vulnerability ingestion

    The Sentinel Data Connectors Reference adds a connector for SAP BTP application vulnerability findings. Using it requires API access and dedicated client credentials. The same update says Corelight deployments now require Reader and Microsoft Graph access in addition to Monitoring Metrics Publisher.

For Defender administrators

Review Teams URL-protection settings and investigation processes; no user action is required for the QR-code rollout. Track the SubmissionEvents and SubmissionResults preview-to-GA transition, although no immediate action or compliance change is stated. For server workflows, review RBAC, device groups, cloud scopes, and offboarding procedures. Update KSPM triage to locate findings against workload controllers. For SAP BTP, enable API access and create dedicated client credentials; Corelight deployments now also require Reader and Microsoft Graph access alongside Monitoring Metrics Publisher.
