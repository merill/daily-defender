Week in brief

Defender XDR plans detection-source targeting for October alert-tuning preview

The period’s main product change is a scheduled Defender XDR alert-tuning enhancement: source-specific rules are due in public preview in mid-October 2026 and general availability in mid-November. Other notable administrator-facing updates cover sensor v2.x directory service accounts, documented WSLc coverage, service-principal RBAC assessment in Cloud Apps, and Foundry disconnection behavior. Most remaining entries refine terminology, inventories, connector references, and procedures.

  • Defender XDR · Incidents and response
    Alert tuning will support detection-source targeting

    Microsoft Defender XDR will allow alert-tuning rules to target specific detection sources. Public preview is scheduled for mid-October 2026, followed by general availability in mid-November; existing rules apply to all sources unless updated. No action is needed unless source-specific customization is desired.

  • Identity · Identity protection
    Sensor v2.x coverage requires a Directory Service Account in specified scenarios

    Updated Identity guidance says sensor v2.x deployments should configure a Directory Service Account for full security coverage. The account is required to access the DeletedObjects container and for certain cross-domain and non-domain-controller scenarios.

  • Endpoint · Endpoint protection
    Defender for Endpoint documentation now lists WSLc support

    The Defender for Endpoint What's New page now lists support for WSL containers (WSLc), extending protection and visibility into WSLc activity. Administrators can include WSLc workloads in Defender for Endpoint protection and monitoring.

  • Cloud Apps · Cloud and workloads
    App Governance guidance adds direct service-principal RBAC assessment

    A new Cloud Apps article explains how to filter, investigate, and assess Microsoft Entra RBAC roles assigned directly to service principals, including permissions, privilege levels, and risk signals. Access to App Governance data and the required App Governance role are prerequisites.

  • Exposure Management · Vulnerabilities and exposure
    Foundry disconnects can disable agentic code scanning without replacement

    Updated Exposure Management guidance says disconnecting Foundry disables agentic code scanning unless another connection is provided. It also clarifies that Standard deployments use each of the three models once and identifies the required model deployments for the Foundry resource.

For Defender administrators

Existing alert-tuning rules will continue applying to all detection sources unless administrators update them for source-specific control. Review sensor v2.x deployments for the required directory service account, use the Cloud Apps prerequisites when assessing service-principal roles, and account for agentic code scanning being disabled if Foundry is disconnected without another connection.
