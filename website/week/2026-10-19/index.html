Week in brief

Defender for Identity v3 guidance details a 30-day opt-out and migration checks

Defender for Identity guidance now documents a concrete sensor v3.x transition path: eligible organizations with an active workspace receive a 30-day banner before v3.x activation and Windows auditing are enabled by default, including settings currently set to Off. Related updates separate v2.x and v3.x deployment, migration, auditing, and connectivity procedures. Defender XDR hunting guidance also renames two CloudDnsEvents columns.

  • Identity · Identity protection
    A 30-day opt-out window precedes documented v3.x default activation

    For eligible organizations with an active Defender for Identity workspace, the banner appears 30 days before sensor v3.x activation and Windows auditing are enabled by default, including settings currently set to Off. Select Opt out within the 30-day window to retain current settings. The same update records Windows Server 2025 sensor migration support as resolved.

  • Identity · Identity protection
    Sensor v3 migration requires the local system account setting

    The migration guide instructs administrators to select “Automatically use the sensor's local system account” before migrating because migration does not change the setting automatically. It also directs them to verify that the setting remains selected rather than using gMSA for action accounts; leaving gMSA selected can affect response actions.

  • Identity · Architecture and deployment
    In-place sensor migration is limited to eligible domain controllers

    Deployment guidance now states that in-place migration from sensor v2.x to v3.x is currently available only for eligible domain controllers, not other servers. Administrators should check server roles and migration prerequisites before planning the transition.

  • Identity · Identity protection
    Automatic auditing guidance now points to System event ID 4697

    The auditing guidance distinguishes automatic Windows auditing for v3.x sensors from automatic sensor activation, updates the listed auditing settings, replaces System event ID 7045 with 4697, and directs administrators to use Certification Authority for certificate-authority auditing.

  • Defender XDR · Hunting and detection
    CloudDnsEvents hunting queries now use EventType and EventSubType

    The table reference replaces DnsEventType and DnsEventSubType with EventType and EventSubType and updates the request-filter example. Review existing CloudDnsEvents queries when adapting them to the revised column names.

For Defender administrators

Identity administrators should verify sensor version and server role before following deployment or troubleshooting procedures. For v3.x migration, select and verify “Automatically use the sensor's local system account”; migration does not change the setting automatically, and gMSA selection can affect response actions. Review the 30-day banner and select Opt out if current settings must be retained. Update CloudDnsEvents queries to use EventType and EventSubType.
