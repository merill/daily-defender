# daily-defender

[daily.defender.admin.news](https://daily.defender.admin.news) — a readable daily
record of what changed across Microsoft Defender documentation.

This repository holds the product: its configuration, its assets, and its
generated site. The generator itself lives in
[merill/dailynews-engine](https://github.com/merill/dailynews-engine), shared
with `daily-intune` and `entra-doc-diff`.

## What it tracks

`MicrosoftDocs/defender-docs`, branch `public` — the fifteen subtrees that
publish to Microsoft Learn, taken from the repository's own
`.openpublishing.publish.config.json`:

| Service | Learn path |
|---|---|
| Defender XDR | `defender-xdr` |
| Defender for Endpoint | `defender-endpoint` |
| Defender for Office 365 | `defender-office-365` |
| Defender for Identity | `defender-for-identity` |
| Defender for Cloud Apps | **`defender-cloud-apps`** |
| Defender for Cloud | **`azure/defender-for-cloud`** |
| Defender for IoT | **`azure/defender-for-iot`** |
| Microsoft Sentinel | **`azure/sentinel`** |
| Defender EASM | **`azure/external-attack-surface-management`** |
| Security Exposure Management | **`security-exposure-management`** |
| Defender Vulnerability Management | `defender-vulnerability-management` |
| Defender for Business | `defender-business` |
| Unified SecOps | `unified-secops-platform` |
| Defender Threat Intelligence | `defender` |

**Six of these publish under a name that is not their folder** — shown in bold.
Those mappings were verified against `learn.microsoft.com` rather than inferred,
because getting one wrong breaks every link for that service without breaking
anything visibly. `src/test-config.js` pins them.

Two pairs also collide on prefix: `defender-for-cloud` would swallow
`defender-for-cloud-apps`, and `defender-for-iot` would swallow
`defender-for-iot-azure`. The route list is ordered so the longer name wins, and
that ordering is asserted rather than assumed.

Not tracked: `advanced-threat-analytics`, which is listed upstream but now holds
only `includes/`; `articles/`, which appears throughout the history and no longer
resolves on Learn; and the `includes/`, `media/` and `breadcrumb/` fragment
directories, which have no URL of their own.

## v1 has no email

`email: { enabled: false }` in `dailynews.config.js`. The site is the whole
product for now — no Kit form, no broadcast workflow, no subscriber list. Turning
it on later means setting `enabled: true`, adding the Kit secrets and restoring
the broadcast workflow from one of the sibling repositories.

`identity.kitMarkerPrefix` is already fixed at `daily-defender-news` so that
turning email on cannot reuse another product's marker.

## The archive is a deterministic backfill

Everything before this site existed was generated by
`scripts/generate-historical-data.js` walking the documentation history from
1 January 2026. Those summaries come from each change's own source metadata, not
from a model — the site says so, on every brief it applies to.

Daily runs from here on are summarised normally. The two are distinguishable:
a backfilled brief reads "assembled from the tracked changes" where a daily one
reads "generated by AI".

## Working on it

```bash
git clone https://github.com/merill/dailynews-engine.git ../dailynews-engine
(cd ../dailynews-engine && npm ci)
npm run engine:link
npm test
npm run build:site && npm run dev
```

`npm run engine:link` points `node_modules` at the sibling engine checkout. In
CI the engine's setup action does the same thing.

## Layout

| | |
|---|---|
| `dailynews.config.js` | everything specific to this product |
| `assets/site/` | favicons, OG image, product and topic icons, shared chrome |
| `website/` | the generated site, committed |
| `src/` | conformance tests for this product's configuration and icons |
| `scripts/` | the engine link helper and the one-shot historical backfill |
